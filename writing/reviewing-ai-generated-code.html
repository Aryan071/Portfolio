A 60-second checklist for reviewing AI-generated code

AI tools write code that looks right. The review job is to find where it is not. This is the checklist I use, in the order I use it.

The six questions

  1. Correctness. Does it do what the ticket says? Does every library and function it calls really exist in the version we use? (Invented APIs are a known failure.)
  2. Security. Is user input used in a query, a file path or a shell command? Is there an authorization check, not only a login check? Are secrets or tokens logged?
  3. Edge cases. Empty input, huge input, None, duplicates, time zones, retries, two requests at the same time.
  4. Tests. Do the tests assert behaviour, or only run the code? Would they fail if the bug came back?
  5. Maintainability. Is it the smallest thing that works? Would a teammate understand it in six months?
  6. Performance. Queries inside loops, no pagination, blocking calls inside async code.

An example

# AI-generated: looks fine
@app.get("/orders/{order_id}")
def get_order(order_id: int, db=Depends(get_db)):
    return db.execute(f"SELECT * FROM orders WHERE id = {order_id}").fetchone()

Problems, most serious first: any logged-in user can read any order (no ownership check), the query is built with string formatting (use bound parameters), and SELECT * returns columns the client should not see.

@app.get("/orders/{order_id}")
def get_order(order_id: int, user=Depends(current_user), db=Depends(get_db)):
    row = db.execute(
        text("SELECT id, status, total FROM orders WHERE id = :id AND user_id = :uid"),
        {"id": order_id, "uid": user.id},
    ).fetchone()
    if row is None:
        raise HTTPException(404)
    return row

How to write the comment

State what you see, why it matters, and a concrete fix. For example: "This lets any user fetch any order by changing the ID. Filter by the current user's ID in the query, and return 404 when nothing matches." Mark each comment as blocking or a suggestion, so the author knows what must change.

Where the checklist stops

It finds bugs a reader can spot. It does not replace running the code, reading the tests, or the CI checks (linters, type checks, security scans). I treat AI output like a pull request from a fast colleague who has never seen our system.
